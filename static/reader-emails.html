Reader Emails

Readers reply to books. Thank-you emails, advance reader copy (ARC) offers, and new-release announcements build relationships — but writing each one from scratch drains energy. This automation drafts them locally so you always have a starting point.

What it does

scripts/draft_reader_email.py drafts one of three email types:

  • thank-you — for a reader who bought or read your book
  • arc — offering an advance reader copy before launch
  • new-release — announcing your book is live with a link

It never sends email — it writes a draft file you open, personalize, and send from your own email app.

Step by step

  1. Try a thank-you draft (dry-run):

    python3 scripts/draft_reader_email.py \
  --type thank-you \
  --reader "Alex" \
  --book "The Massive AI Manual"

    Review it on screen. Nothing is saved yet.

  2. Write the draft to a file:

    python3 scripts/draft_reader_email.py \
  --type thank-you \
  --reader "Alex" \
  --book "The Massive AI Manual" \
  --apply

    This creates reader-emails/email-draft.md. Open it in any text editor, change the wording to sound like you, then copy it into your email app and send.

  3. Try the other types: swap --type for arc or new-release. For new-release, add --link "https://example.com/book".

  4. Use test names, not real data. While practicing, use names like "Alex." Never paste real reader addresses, order IDs, or personal details into these files.

Options you can use

OptionWhat it doesExample
--typeEmail type: thank-you, arc, new-release--type arc
--readerReader's name--reader "Alex"
--bookBook title (required)--book "My Book"
--linkBook link for new-release emails--link "https://example.com"
--outWhere to write the draft--out reader-emails/august.md
--applyActually write the file(no value needed)

Low-energy tip: if email feels overwhelming, draft one email per week with this script and send it on the same day each week. If you don't hear back, that's fine — the email still did its job.
